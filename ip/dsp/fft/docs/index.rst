.. _ip-fft:

===
fft
===

Burst radix-2 FFT/IFFT of ``2**N_LOG2`` complex points: load a frame, transform
it in place with one butterfly per cycle, unload it in natural order.

Functional description
======================

What it computes
----------------

.. code-block:: text

   X[k] = (1/N) * sum over n of x[n] * exp(-+ j*2*pi*n*k/N)

The minus sign is the forward transform; a frame loaded with ``inverse``
high uses the plus sign. The 1/N is the fixed scaling that keeps the
arithmetic in range - a halving at every stage - so the inverse transform is
exact in scale and the forward one is off by the usual factor N.

Algorithm
---------

Decimation in time, in place, in one frame memory:

1. **Load.** The ``N`` input samples are written at bit-reversed addresses
   as they arrive, so that the butterflies leave the result in natural
   order.
2. **Compute.** ``N_LOG2`` stages of ``N/2`` butterflies, one per cycle.
   Stage ``s`` pairs points ``half = 2**s`` apart; butterfly ``j`` works on

   .. code-block:: text

      i0 = (j / half) * 2*half + (j mod half),   i1 = i0 + half
      w  = exp(-+ j*2*pi*(j mod half) / (2*half))
      t  = w * x[i1]
      x[i0] = (x[i0] + t) / 2,   x[i1] = (x[i0] - t) / 2

3. **Unload.** The bins leave in natural order, ``m_last`` on bin ``N-1``.

The block holds one frame: the next frame loads once the current one has been
unloaded. A frame takes ``N`` cycles to load, ``(N/2) * N_LOG2`` to transform
and ``N`` to unload under no back-pressure.

Twiddles
--------

Twiddles are Q1.15 (``32767`` is one) from ``fft_twiddle``, a ROM holding a
quarter of a cosine at the largest supported size, 1024 points; every smaller
size uses every ``(1024 >> N_LOG2)``-th entry, and the other quadrants follow
from symmetry. The ROM is generated by ``scripts/gen_twiddle.py`` because no
synthesis tool the portfolio targets evaluates ``$cos`` at elaboration; the
cocotb model builds its twiddles from the same formula, so a stale table
fails the regression, and ``gen_twiddle.py --check`` reports one directly.

Fixed point
-----------

The complex product ``t = w * b`` is rounded half up from Q1.15 back to the
data's scale, and each halving is rounded half up too. The halving keeps a
part within range except where a rotation lines a vector up with an axis: a
sum of two full-scale parts can reach ``(1 + sqrt 2) / 2`` of full scale. Each
butterfly output is therefore saturated, and ``m_overflow``, held for the
whole output frame, reports a frame in which any was. Inputs within about
0.4 of full scale never saturate.

Block diagram
=============

.. code-block:: text

   s_re/s_im --> [bit reverse] --> frame memory (N complex words)
                                    |  read x[i0], x[i1]      ^ write both
                                    v                         |
                     fft_twiddle --> butterfly: w*b, (a+-t)/2, saturate
                                    |
                                    +--> natural-order unload --> m_re/m_im

Integration notes
-----------------

* For a continuous stream, place two instances behind a demultiplexer, or a
  FIFO in front sized for the compute time: the block is a burst engine.
* The frame memory is flip-flops, so ``N_LOG2`` above 8 is better served by
  a memory-based variant; the RTL is written so that the memory accesses -
  two reads and two writes per butterfly - are explicit.
* Window the input in the upstream logic if spectral leakage matters.

Verification
============

.. list-table::
   :header-rows: 1

   * - Suite
     - Contents
   * - ``cocotb/test_fft.py``
     - A bit-exact model of the algorithm above. Covers the reset state, an
       impulse and DC, a tone in every bin, the inverse transform, the exact
       frame cycle count, ``m_overflow`` for each of the four butterfly
       outputs saturating alone - in frames built to do exactly that, since

       gaps and back-pressure, and every frame within a rounding bound of

   * - ``tb/tb_fft.sv``
     - An independent reference: a direct O(N**2) DFT in real arithmetic,
       with no butterflies, bit reversal or twiddle ROM. 120 random frames,
       forward and inverse, every bin within the bound, ``m_last`` and the
       frame timing checked.

.. code-block:: bash

   ctest --test-dir build -R 'fft'

Timing
======

Timed by OpenSTA at the period in the ``add_ip()`` registration. The
critical path is one butterfly: the ``N:1`` read multiplexer, a complex
multiply, the sums, the halving and the saturation, back into the frame
memory.
